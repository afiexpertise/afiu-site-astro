# Résumé

Utiliser Vibe CLI pour travailler directement dans un projet local avec contrôle des fichiers, commandes, scripts et permissions.

Le cours s'inscrit dans le fil rouge du cursus : **une demande reçue par courriel ouvre une tâche que le collaborateur doit conduire de bout en bout avec l'aide de l'assistant IA**.

# Positionnement dans le cursus

- **Parcours :** Cursus IA orienté tâches
- **Produit :** Mistral Vibe / Vibe Code
- **Ordre :** 8
- **Durée :** 210 minutes

# Compétences couvertes

- **IA-130 — Comprendre le fonctionnement général d’un orchestrateur IA**
- **IA-240 — Identifier objectif, contexte, attentes et sources**
- **IA-320 — Évaluer la qualité d’une réponse**
- **IA-420 — Utiliser le Context Engineering**
- **IA-460 — Utiliser les contraintes**
- **IA-510 — Collaborer avec l’IA**
- **IA-610 — Protéger les données**
- **IA-620 — Gérer les risques associés à l’IA**

# Objectifs pédagogiques

1. Démarrer Vibe CLI dans un projet.
2. Contrôler fichiers et commandes accessibles.
3. Faire planifier avant action.
4. Exécuter une maintenance ou correction.
5. Vérifier tests et changements.

# Agenda — théorie

- Client CLI et contexte du projet.
- Accès fichiers et shell.
- Permissions et commandes.
- Scripting et automatisation contrôlée.
- Tests, diff et reprise.

# Fil rouge — expérimentation personnelle

**État entrant :** La solution issue du fil rouge doit être maintenue directement dans l'environnement local.

1. Ouvrir Vibe CLI dans le projet.
2. Faire inspecter l'état sans modification.
3. Demander une tâche de maintenance ciblée.
4. Faire exécuter les tests nécessaires.
5. Inspecter les changements et confirmer ou annuler.

**État sortant :** Le participant sait collaborer avec Vibe depuis le terminal tout en contrôlant les opérations locales.

# Réflexion et questions de groupe

- **Quand le terminal est-il le meilleur espace de collaboration?**
- **Quelles commandes ne devraient jamais être automatiques?**
- **Comment garder une tâche locale reproductible?**

# Validation

Le participant doit pouvoir expliquer ce qu'il a confié à l'IA, identifier les sources utilisées, vérifier le résultat produit et déterminer si la tâche peut progresser vers l'étape suivante.
