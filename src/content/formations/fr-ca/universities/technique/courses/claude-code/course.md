# Résumé

Utiliser Claude Code pour comprendre un projet, planifier une modification, changer le code et vérifier le résultat.

Le cours s'inscrit dans le fil rouge du cursus : **une demande reçue par courriel ouvre une tâche que le collaborateur doit conduire de bout en bout avec l'aide de l'assistant IA**.

# Positionnement dans le cursus

- **Parcours :** Cursus IA orienté tâches
- **Produit :** Anthropic Claude / Claude Code
- **Ordre :** 8
- **Durée :** 210 minutes

# Compétences couvertes

- **IA-130 — Comprendre le fonctionnement général d’un orchestrateur IA**
- **IA-240 — Identifier objectif, contexte, attentes et sources**
- **IA-320 — Évaluer la qualité d’une réponse**
- **IA-420 — Utiliser le Context Engineering**
- **IA-450 — Utiliser le raisonnement guidé**
- **IA-460 — Utiliser les contraintes**
- **IA-510 — Collaborer avec l’IA**
- **IA-620 — Gérer les risques associés à l’IA**

# Objectifs pédagogiques

1. Transformer un besoin du fil rouge en tâche technique.
2. Faire comprendre une codebase à l'agent.
3. Planifier avant modification.
4. Utiliser outils et tests.
5. Revoir les changements et risques.

# Répartition pédagogique

| Bloc | Durée | Part | Finalité |
| --- | ---: | ---: | --- |
| Théorie et démonstration guidée | 63 min | 30 % | Comprendre les concepts, capacités, limites et règles d'usage |
| Expérimentation personnelle du fil rouge | 126 min | 60 % | Réaliser concrètement une partie de la tâche avec l'assistant |

# Agenda — théorie

- Codebase, contexte et instructions.
- Plan et sous-tâches.
- Outils, MCP et accès externes.
- Tests, débogage et itération.
- Revue, sécurité et responsabilité.

# Fil rouge — expérimentation personnelle

**État entrant :** Une partie répétitive de la tâche nécessite une solution logicielle.

1. Décrire le besoin métier et les critères de succès.
2. Faire explorer le projet avant modification.
3. Demander et valider un plan.
4. Faire modifier le code et exécuter les tests.
5. Inspecter les changements avant adoption.

**État sortant :** Une modification logicielle testée soutient concrètement le fil rouge.

# Réflexion et questions de groupe

- **Quelles décisions techniques doivent rester humaines?**
- **Quel contexte est indispensable avant de modifier du code?**
- **Comment traiter un test qui passe mais un besoin qui n'est pas satisfait?**

# Validation

Le participant doit pouvoir expliquer ce qu'il a confié à l'IA, identifier les sources utilisées, vérifier le résultat produit et déterminer si la tâche peut progresser vers l'étape suivante.
